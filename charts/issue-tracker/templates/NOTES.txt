Issue Tracker is installed with one replica and Recreate updates because its SQLite database uses a ReadWriteOnce volume.

If this is a new installation, do not expose it publicly yet. Claim the first administrator through private access as described in docs/deployment.md, then configure the final BASE_URL and ingress.

The PVC is annotated with helm.sh/resource-policy: keep and is intentionally retained by `helm uninstall`. Back up both the SQLite database and uploads under /data, plus the matching settings-key Secret.

Workspace migration: on the FIRST migration to database version 22, existing content is placed in {{ .Values.migration.workspaceName | quote }} (slug {{ .Values.migration.workspaceSlug | quote }}). Changing these values after migration does not rename the workspace. URLs now include /w/<workspace-slug>.

Read the packaged chart README migration instructions before upgrade. Stop writes and verify a complete backup. Do not use --atomic or an image-only Helm rollback after migration: restore the pre-upgrade data and matching chart/image together.
