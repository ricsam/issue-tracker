Threadline is an MIT-licensed Bun/TypeScript application. The public repository is [ricsam/issue-tracker](https://github.com/ricsam/issue-tracker). The web UI is the primary API client; the JSON API is useful for same-origin automation but is not a versioned public SDK.

## Development workflow

```sh
git clone https://github.com/ricsam/issue-tracker.git
cd issue-tracker
bun install
cp .env.example .env
```

Run the API and Vite in separate terminals:

```sh
bun dev
```

```sh
bun dev:web
```

Before opening a pull request:

```sh
bun run typecheck
bun run test
bun run build
bunx playwright install chromium
bun run test:e2e
```

Add tests for behavior changes and avoid committing dependencies, build output, `.env`, data files, or credentials. Deployment changes should also pass the chart's lint and template checks documented in the repository.

## API conventions

- Every response is JSON except redirects and authenticated file downloads. Errors have shape `{ "error": "message" }`.
- Authentication uses an HTTP-only, SameSite=Lax session cookie. It is `Secure` when the configured origin is HTTPS.
- Unsafe methods (`POST`, `PUT`, `PATCH`, and `DELETE`) require an `Origin` header exactly matching `BASE_URL`.
- All `/api` routes require authentication except auth status, first setup, local login, and the OIDC redirect/callback flow.
- Canonical issue and comment bodies are Markdown, not HTML.
- API objects and enums are declared in `shared/types.ts`.

<Warning>
Do not put the API behind a proxy that strips the browser `Origin` header or changes the externally visible origin without updating `BASE_URL`. Do not use an administrator's persistent browser cookie as a general-purpose API token.
</Warning>

## Authentication and users

| Method | Path | Body or result |
| --- | --- | --- |
| `GET` | `/api/auth/status` | Setup state, current user, and public OIDC display state |
| `POST` | `/api/auth/setup` | `{name,email,password}`; succeeds only when there are zero users |
| `POST` | `/api/auth/login` | `{email,password}`; starts a local session |
| `POST` | `/api/auth/logout` | Invalidates the current session |
| `GET` | `/api/auth/oidc/login` | Redirects to the configured provider |
| `GET` | `/api/auth/oidc/callback` | Completes state, PKCE, nonce, token, and identity validation |
| `GET` | `/api/users` | `{users: User[]}` for authenticated users |
| `POST` | `/api/admin/users` | Administrator creates a local member from `{name,email,password}` |
| `GET` | `/api/admin/oidc` | Administrator-only settings without the client secret |
| `PUT` | `/api/admin/oidc` | Updates provider settings; omitted or empty `clientSecret` preserves it |

The OIDC callback keys identities by immutable issuer and subject. Verified email is profile data and never performs account linking.

## Projects and issues

| Method | Path | Notes |
| --- | --- | --- |
| `GET` | `/api/projects` | All shared projects with issue/open counts |
| `POST` | `/api/projects` | `{name,description?}`; generated slug is stable |
| `GET` | `/api/projects/:slug` | One project |
| `PATCH` | `/api/projects/:slug` | `{name?,description?}` edits active project metadata without changing its slug; `{archived: boolean}` separately archives or restores |
| `GET` | `/api/projects/:slug/issues` | All project issues; UI filtering is client-side |
| `POST` | `/api/projects/:slug/issues` | `{body,labels?,title?}`; number increments within the project |
| `POST` | `/api/projects/:slug/issues/tag` | `{issueIds,userIds}` → `{issues}`; atomic addition of body mentions |
| `POST` | `/api/projects/:slug/issues/labels` | `{issueIds,labels}` → `{issues}`; atomic addition of body hashtags |
| `GET` | `/api/projects/:slug/board` | `{board: BoardSettings}` |
| `PATCH` | `/api/projects/:slug/board` | `{lanes,customLanes?}`; returns `{board: BoardSettings}` |
| `GET` | `/api/issues/:id` | `{issue,comments}` |
| `PATCH` | `/api/issues/:id` | Any authenticated user may update supplied issue fields, including `state` |

Issue fields include Markdown `body`, derived display `title`, `labels`, `taggedUserIds`, and `state` (`open` or `closed`, derived from nullable `closedAt` with `closedById`). Labels come from hashtags in saved issue-body prose, with at most 30 values of up to 50 characters on writes. Code, links, URLs and images are excluded, and comments do not add labels. Escaped Markdown hashes count when rendered as hashtags. Legacy `labels` input is additive: it adds missing body hashtags rather than replacing the label list. Remove body hashtags to remove labels. Migration v8 preserves original content, stored titles, timestamps and lifecycle history while adding missing legacy labels, using extended syntax such as `#[needs%20review]` for spaces/punctuation. There is no assignee field; POST and PATCH reject `assigneeId`. User associations come only from saved mentions in the issue and its comments.

Body-only creation and body updates require non-whitespace content, with a 101,000-character limit (`ISSUE_BODY_MAX_LENGTH` in `shared/issue-content.ts`). `deriveIssueTitle(body)` selects the first real ATX/setext heading outside code, otherwise the first meaningful text line, strips common inline formatting and link destinations, and limits the display cache to 300 characters. Image/code-only content can display `Untitled issue`. State-only PATCH preserves body and title.

Legacy clients may still send a nonempty `title` of up to 300 characters: POST and PATCH with a body merge it as an escaped leading heading, avoiding an equivalent existing heading. Title-only PATCH replaces or adds the leading heading without losing the remainder. The final merged body must fit the body limit. On upgrade, transactional SQLite migration v3 moves old titles into escaped leading headings, preserves original body bytes and timestamps/metadata, and recomputes display titles. Reopening does not repeat the migration.

`BoardSettings` is `{lanes: Lane[], customLanes: BoardLane[], cards: BoardCard[]}`, with definitions `{value,label}` and cards `{issueId,lane}`. New boards show `todo`, `in_progress`, and `done` with no cards. Settings PATCH changes visibility, order and custom definitions, never membership. Hidden lanes retain their cards. Issue creation rejects `addToBoard` and never adds board membership automatically.

Board membership uses `POST /api/projects/:slug/board/issues` with `{issueIds,lane}` (atomic add), `PATCH /api/projects/:slug/board/issues/:id` with `{lane}` (move), and `DELETE` on that same issue route (remove). Each returns `{board}`. Bulk moves/removals in the UI use individual requests, retaining failed selections for retry; they are not atomic batches.

Bulk tagging accepts 1–1000 unique UUIDs in each of `issueIds` and `userIds`. All issues must belong to the project and users must exist. The whole batch rolls back on error, including body-limit errors. Missing body mentions are inserted without rewriting original content or comments; stored titles are preserved, and repeat requests do not duplicate mentions or change timestamps. Comment-only mentions still receive a body mention. Archived projects reject tagging. This endpoint requires the same cookie authentication and Origin protection as other writes.

Bulk hashtags accept 1–1000 unique issue UUIDs and 1–30 trimmed, nonempty label names of at most 50 characters, without the `#` prefix. Missing hashtags are appended to the latest body (or inserted before an unclosed Markdown block), preserving original content, titles, mentions, comments and lifecycle/board data. Existing hashtags are not duplicated and no-op retries keep timestamps unchanged. All issues must belong to the project; archived projects reject changes. Authentication, Origin checks, body/combined-label limits and atomic rollback apply to the whole batch.

Projects and issues have no delete endpoint. Close an issue with `state: "closed"` and archive a project with `archived: true`; both are reversible. Archived projects (`archivedAt` set) stay readable, but issue, comment, and board writes return `409 Project is archived` until the project is restored.

## Comments and uploads

| Method | Path | Notes |
| --- | --- | --- |
| `POST` | `/api/issues/:id/comments` | `{body}` creates a Markdown comment |
| `PATCH` | `/api/comments/:id` | Author or administrator updates body |
| `DELETE` | `/api/comments/:id` | Author or administrator deletes comment |
| `POST` | `/api/uploads` | Multipart form with field `file`, at most 10 MiB |
| `GET` | `/api/uploads/:id/:name` | Authenticated download; exact stored name must match |

Comment bodies require non-whitespace content and have a 100,000-character limit.

PNG, JPEG, GIF, and WebP bytes are signature-sniffed and may render inline. Other files are downloaded with a restrictive content disposition, `nosniff`, and sandbox CSP. A supplied MIME type alone cannot make an arbitrary file render as an image. Uploads are workspace-wide and retained even if no content references them.

## Health endpoints

`GET /healthz` and `GET /readyz` are deliberately public and minimal. Readiness executes a database query. Do not place secrets or detailed infrastructure state in probe responses.

## Editor component contract

`RichEditor` from `src/components/rich-editor.tsx` accepts `value: string`, `onChange: (markdown: string) => void`, and optional `placeholder?: string`, `minimal?: boolean`, `ariaLabel?: string`, and `autoFocus?: boolean`. Issue creation uses the single editor with autofocus. `Markdown` from `src/components/markdown.tsx` renders the saved body.

## Documentation contributions

The Mintlify project root is `docs/`. Preview and validate it using the commands in `docs/README.md`. Existing `docs/*.md` files are implementation and operator source references; the rendered site uses the MDX pages declared in `docs/docs.json`.

Security reports should follow the repository's `SECURITY.md`, not a public issue.
