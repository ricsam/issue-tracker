title: Issues

An issue holds one Markdown body, labels, tagged users, and an open or closed state. There is no assignee or assignment role.
Its display title is derived from that body rather than entered in a separate field.
Its discussion keeps comments alongside the work.
All authenticated users can read and update issues across all projects.

## Create an issue

1. Open the project that should contain the work.
2. Select **Create issue** from either **List** or **Board**.
3. Start typing in the single issue editor, which receives focus when the creation dialog opens. Use a heading for the desired outcome, followed by context, reproduction steps, or a checklist.
4. Optionally enter comma-separated labels.
5. Select **Create issue** to save. The dialog clears and refocuses for another issue; select **View issue** in the confirmation to open it, or **Done** to close the dialog.

New issues are open and stay off the board until you [add them to it](/guides/board).
The issue body must contain non-whitespace content; labels may be empty.
Numbers are allocated within each project, not across the entire workspace.

## Choose useful properties

| Property | Available values or limits |
| --- | --- |
| Issue body | Required Markdown; up to 101,000 characters |
| Display title | Derived from the body; up to 300 characters |
| State | Open or Closed |
| Tagged users | Deduplicated users mentioned in the saved issue or its comments |
| Labels | Up to 30 entries, each up to 50 characters |

Enter labels such as `bug, checkout, mobile` in the **Labels** field.
The interface trims surrounding whitespace, ignores empty entries, and removes exact duplicates.
Type `@` and select a teammate in an issue or comment to associate them with the issue. Tags have no roles, ownership, or notification behavior and do not restrict editing. Removing a user's last saved mention removes their association.

## How display titles work

The first Markdown heading outside code supplies the title shown in lists and board cards.
Without a heading, Threadline uses the first meaningful text line, removes common inline formatting and link destinations, and limits the display to 300 characters.
Image-only or code-only content can display **Untitled issue**.
The full Markdown body remains available when you open the issue.

On upgrade, existing titles become escaped leading Markdown headings above their original descriptions, unless an equivalent heading is already present.
This automatic migration preserves the original description bytes, timestamps, and other issue metadata and does not repeat on restart.

## Edit and save

Open an issue by selecting its title in the list or board.
Change the Markdown body or properties, then select **Save changes**.
Edit the heading or first text line in the body to change the derived display title.
Wait for **Changes saved** before leaving the page.
Edits on the detail page are not automatically saved.
When switching issues in the desktop side panel, the previous issue remains visible but non-interactive while the new one loads. A failed load shows an error and **Retry** without replacing the previous content.

<Note>
  **Close issue** and **Reopen issue** save immediately.
  They neither save nor discard other unsaved edits on the page.
</Note>

Use [rich text and Markdown](/guides/rich-text) for structured issue bodies.
Use [uploads](/guides/uploads) for screenshots and supporting files.
Wait for an upload to finish before saving the surrounding content.

## Find an issue

Within a project, **Search issues** matches title text, issue numbers, and labels without case sensitivity.
It does not search the full issue body or comments.
The list shows **Open** issues by default; select **Closed** to see closed ones.
Search applies within the selected state, so check **Closed** if an expected issue is missing.

Click a column heading to sort, or its filter button to open column filters. Filters combine with search and the selected state; created-date ranges include both boundary dates. **Clear column filters** resets filters without changing the sort.

The list shows 25 rows per page by default. Use **Rows per page** to choose 10, 25, 50, or 100, and **Previous**/**Next** to navigate. Changing search, filters, sort, or issue state returns to the first page.

## Add to the discussion

Write in **Add a comment**, then select **Post comment**.
Comments must contain non-whitespace content and may be up to 100,000 characters.
Posting a comment is separate from saving changes to the issue itself.
Closed issues still accept comments.

The comment author and administrators can select **Edit comment**, then **Save comment**.
They can also select **Delete comment** and confirm with **Confirm delete**.
Other members can read the discussion and post their own comments, but cannot edit someone else's comment.

<Warning>
  Comment deletion is permanent and has no undo action.
  Comments are the only content with a deletion action: projects, issues, and uploaded files are retained.
  Deleting a comment does not remove its uploaded files.
</Warning>

## Close or reopen an issue

Select **Close issue** in the issue details when the work is finished or no longer needed.
The issue shows a **Closed** badge, records who closed it and when, and moves from **Open** to **Closed** in the list.
It keeps its content and comments, can still be edited, and still counts toward the project's total issue count.
Select **Reopen issue** to return it to the open list.

To close several open issues, select their checkboxes and choose **Close selected issues**. The header checkbox selects open issues on the current page only; selections persist across pages but hidden or closed issues are removed from the selection. **Clear selection** deselects everything. If some closes fail, successful ones stay closed and failed ones remain selected for retry. Closing an issue with a pending draft in the side panel asks before discarding that draft. Closed issues and archived projects cannot be selected for bulk closing.

Closing never changes the board: a closed issue keeps its lane, and its card shows a **Closed** tag.
Move the card to **Done** or remove it from the board if you want it out of the way.
**Add issues** offers only open issues.
For a visual workflow, continue with [the board guide](/guides/board).

Issues in an [archived project](/guides/projects#archive-a-project) are read-only, including their state, until the project is restored.
