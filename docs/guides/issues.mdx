An issue holds one Markdown body, tags, tagged users, and an open or closed state. There is no assignee or assignment role.
Its display title is derived from that body rather than entered in a separate field.
Its discussion keeps comments alongside the work.
All authenticated users can read and update issues across the workspace. Issues can belong to a project or be unlinked.

## Create an issue

1. Select **Create issue** in the sidebar or press **Alt+N**. You can also create from a project's **List** or **Board**.
2. Choose an active **Project** or **No project**. On project pages the current project is preselected; elsewhere creation defaults to no project.
3. Start typing in the single issue editor, which receives focus when the creation dialog opens. Use a heading for the desired outcome, followed by context, reproduction steps, or a checklist.
4. Optionally add tags such as `#bug` or `#needs-review` to the body.
5. Select **Create issue** to save. The dialog clears and refocuses for another issue; select **View issue** in the confirmation to open it, or **Done** to close the dialog.

New issues are open and stay off the board until you [add them to it](/guides/board).
The issue body must contain non-whitespace content; tags may be empty.
Numbers are allocated from one global sequence across all projects and unlinked issues, displayed as `!12`, with URLs such as `/issues/12`. Existing issues cannot yet be reassigned; unlinked issues cannot join project boards.

## Tags, mentions and issue references

| Property | Available values or limits |
| --- | --- |
| Issue body | Required Markdown; up to 101,000 characters |
| Display title | Derived from the body; up to 300 characters |
| State | Open or Closed |
| Tagged users | Deduplicated users mentioned in the saved issue or its comments |
| Tags | Up to 30 entries, each up to 50 characters |

Tags come from `#tag` text in saved issue prose, including Unicode tags. Type `#` in Write or Markdown mode to find existing tags from this project. Use Up/Down and Enter/Tab, or click a suggestion; Escape dismisses the menu. Keep typing to use a new tag. Remove the tag from the body to remove it. Code, links, URLs, and images do not create tags, and tags in comments do not affect the issue’s tags. Escaped hashes in Markdown still count when rendered as tags. Tags containing spaces or punctuation use extended syntax such as `#[needs%20review]`; existing tags are migrated without removing original content or changing stored titles or timestamps.
Type `@` and select a teammate in an issue or comment to associate them with the issue. Mentions have no roles, ownership, or notification behavior and do not restrict editing. Removing a user's last saved mention removes their association.

Type `!` in an issue or comment in Write or Markdown mode to reference another issue. Search by number or title across the whole workspace, including closed and archived issues. Use Up/Down and Enter/Tab, or click a suggestion; Escape dismisses the menu. Plain `!12` renders as a link to issue 12; `#12` is a tag, not an issue reference. Code, images, URLs and existing links are not interpreted as references.

On upgrade, existing issues receive global numbers in creation order while their content, comments, board placement/order and lifecycle stay intact. Use the new numeric URLs; old UUID links are not supported. Back up before upgrading; restoring an earlier app requires restoring the matching database backup.

## How display titles work

The first Markdown heading outside code supplies the title shown in lists and board cards.
Without a heading, Threadline uses the first meaningful text line, removes common inline formatting and link destinations, and limits the display to 300 characters.
Image-only or code-only content can display **Untitled issue**.
The full Markdown body remains available when you open the issue.

On upgrade, existing titles become escaped leading Markdown headings above their original descriptions, unless an equivalent heading is already present.
This automatic migration preserves the original description bytes, timestamps, and other issue metadata and does not repeat on restart.

## Edit and save

Open an issue by selecting its title in the list or its card body on the board. Full-page issues have a top breadcrumb back to the project, or **All issues** when unlinked. Creation metadata appears beside the issue number and state; there is no separate properties card or tag list.
The issue body opens in **Preview**, both on the full page and in the desktop side panel. Select **Write** or **Markdown** to edit it, then select **Save changes**, or press Cmd+S on macOS / Ctrl+S elsewhere while focused on the issue. New issues and comment editors still start in **Write** mode.
Edit the heading or first text line in the body to change the derived display title.
Wait for **Changes saved** before leaving the page.
Edits on the detail page are not automatically saved.
When switching issues in the desktop side panel, the previous issue remains visible but non-interactive while the new one loads. A failed load shows an error and **Retry** without replacing the previous content.

<Note>
  **Close issue** and **Reopen issue** save immediately.
  They neither save nor discard other unsaved edits on the page.
</Note>

Use [rich text and Markdown](/guides/rich-text) for structured issue bodies.
Use [uploads](/guides/uploads) for screenshots and supporting files.
Wait for an upload to finish before saving the surrounding content.

## Keyboard shortcuts

Hover **Create issue** or **Save changes** to see its shortcut. Cmd+N on macOS / Ctrl+N elsewhere opens a new issue anywhere in the workspace when the browser allows it. Choose a project or leave it unlinked. Some browsers reserve that key for a new window; use **Alt+N** instead. While focus is inside the Create issue dialog, **Cmd+Enter** on macOS / **Ctrl+Enter** elsewhere creates the draft in Write, Markdown, or Preview mode. The dialog stays open with a blank editor for the next issue. Empty drafts, held-key repeats, and shortcuts during a pending request do not submit. Cmd/Ctrl+S still saves the focused issue or creates the focused new draft, without submitting a comment or saving an issue behind another dialog.

## Find an issue

Open **All issues** in the sidebar to see issues from every project and issues with no project. Use the filter beside the **Project** column heading to choose a specific project or **No project**. Archived-project issues remain visible but read-only, and their checkboxes are disabled. All other table controls, including bulk actions, work across projects and unlinked issues.

Within either a project or **All issues**, **Search issues** matches title text, issue numbers, tagged users, and tags without case sensitivity.
It does not search the full issue body or comments.
The list shows **Open** issues by default; select **Closed** to see closed ones.
Search applies within the selected state, so check **Closed** if an expected issue is missing.

The **Board lane** column shows each issue's actual board placement, including custom lanes. Hidden lanes are marked **(hidden)**; unplaced and unlinked issues show **Not on board**. Use its filter to see a specific lane or issues not on a board. In **All issues**, each lane option includes its project name so same-named lanes from different projects remain distinct. Closed issues retain their board lane, and placement changes from **Send to board** update the column immediately.

Click a column heading to sort, or its filter button to open column filters. Filters combine with search and the selected state; created-date ranges include both boundary dates. **Clear column filters** resets filters without changing the sort.

The list shows 25 rows per page by default. Use **Rows per page** to choose 10, 25, 50, or 100, and **Previous**/**Next** to navigate. Changing search, filters, sort, or issue state returns to the first page.

Use Up/Down to open adjacent issues, including across page boundaries. Shift+Up/Down or Shift-click selects a range in the current filtered and sorted order.

Select issues and choose **Tag selected issues** to add teammates as saved body mentions. Existing body mentions are not duplicated, and original content is preserved. Users already mentioned only in comments still receive a body mention. Archived projects cannot be tagged.

Select issues in the list or board and choose **Add tags** to tag them together. Choose existing tags, type new tags such as `#bug #needs-review`, or combine both. Use `#[needs review]` for tags containing spaces. The preview shows the tags that will be added.

Tags are appended to each selected issue’s latest saved body without replacing text or duplicating existing tags. If an unclosed Markdown block would hide the tags, they are inserted near the top instead. Closed issues can be tagged; archived projects are read-only. If a selected issue has an unsaved draft, you are asked before discarding it. A failed batch leaves all issues unchanged and keeps the dialog open for retry.

## Send issues to a board lane

Select one or more issues in a project list or **All issues**, then choose **Send to board**. The same action is available in full-page issue details and the desktop detail panel.

Choose a visible lane for each project's selected issues. The choices include that board's custom lanes. Issues not yet on the board are added; existing cards move to the chosen lane, including cards currently in hidden lanes. A single issue already on the board defaults to its current lane when visible.

- Unlinked issues have no board and are skipped with an explanation. Archived projects are read-only.
- Closed issues already on a board can move. Reopen closed off-board issues before adding them.
- Each project's changes are atomic, with a maximum of 1,000 issues per project. If one project fails, other successful projects stay saved. Retry only the remaining projects, or reload their lanes if the board changed.
- Successfully sent issues are deselected; failed or skipped issues remain selected. Select **Done** to return to the list or issue.
- Placement changes only the board. It neither saves nor discards unsaved issue edits or comments, and it does not change issue state.

## Add to the discussion

Write in **Add a comment**, then select **Post comment**. An empty discussion shows only the comment editor, without an empty-state message.
Comments must contain non-whitespace content and may be up to 100,000 characters.
Posting a comment is separate from saving changes to the issue itself.
Closed issues still accept comments.

The comment author and administrators can select **Edit comment**, then **Save comment**.
They can also select **Delete comment** and confirm with **Confirm delete**.
Other members can read the discussion and post their own comments, but cannot edit someone else's comment.

<Warning>
  Comment deletion is permanent and has no undo action.
  Comments are the only content with a deletion action: projects, issues, and uploaded files are retained.
  Deleting a comment does not remove its uploaded files.
</Warning>

## Close or reopen an issue

Select **Close issue** in the issue details when the work is finished or no longer needed.
The issue shows a **Closed** badge, records who closed it and when, and moves from **Open** to **Closed** in the list.
It keeps its content and comments, can still be edited, and still counts toward the project's total issue count.
Select **Reopen issue** to return it to the open list.

To close several open issues, select their checkboxes and choose **Close selected issues**. The header checkbox selects issues on the current page only; selections persist across pages but filtering removes hidden issues. Only selected open issues are closed. **Clear selection** deselects everything. If some closes fail, successful ones stay closed and failed ones remain selected for retry. Closing an issue with a pending draft in the side panel asks before discarding that draft. Closed issues can be selected for tagging, but cannot be closed again. Archived projects cannot use bulk actions.

Closing never changes the board: a closed issue keeps its lane, and its card shows a **Closed** tag.
Move the card to **Done** or remove it from the board if you want it out of the way.
**Add issues** offers only open issues.
For a visual workflow, continue with [the board guide](/guides/board).

Issues in an [archived project](/guides/projects#archive-a-project) are read-only, including their state, until the project is restored.
