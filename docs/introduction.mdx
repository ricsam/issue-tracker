## A deliberately shared workspace

Public projects are shared with all signed-in users. Private projects are limited to their owner, explicitly shared users, and administrators. Owners and administrators manage project access; readable projects remain collaborative. Administrators also manage local users and OIDC settings. Comments require project access and can be edited or deleted only by their author or an administrator.

<Warning>
Public never means anonymous access. Issues without a project remain workspace-wide. Uploaded attachments follow readable saved issue, comment, or history references; unsaved uploads are private to the uploader and administrators. Moving or sharing content can broaden its audience.
</Warning>

## Small by design

- **Bun and Hono** serve the API and the built Vite frontend from one process.
- **React and Lexical** provide issue views and rich Markdown editing.
- **SQLite** stores workspace records and encrypted OIDC client-secret settings.
- **Local uploads** live alongside the database in the persistent data directory.
- **One replica** keeps storage and upgrades straightforward; this is not a highly available deployment.

## Start safely

The first local account becomes the administrator. An unclaimed instance is not safe to expose publicly: create that account over private access before enabling ingress. Production requires an HTTPS external origin and a stable settings-encryption key.

Read [first administrator setup](/admin/setup) before publishing a deployment, and review [first-release boundaries](/admin/limitations) before adopting Threadline for a team.
